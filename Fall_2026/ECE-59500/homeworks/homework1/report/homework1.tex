\section{Building ARM binaries}

Let's save the file \filepath{babysteps.s} with the recommended formatting:

\begin{codebox}[asm]{babysteps.s}
.global _start

_start:
top:
    eor r1, r1
    b top
\end{codebox}

To build this, I ran the commands recommended in the readings:

\TermHost{ricardo}
\TermPath{homework1}
\TermTitle{Terminal}
\begin{terminal}
\cmd{arm-none-eabi-as babysteps.s -o babysteps.o}
\cmd{arm-none-eabi-ld -g babysteps.o -o babysteps.elf}
\end{terminal}

Investigating by myself, I was able to understand what those commands do:

\begin{itemize}
    \item The first command \filepath{arm-none-eabi-as} builds an object file for ARM architecture.
    It reads the file \filepath{babysteps.s} and then the flag \code{-o} indicates the output path \filepath{babysteps.o}.
    \item The second command \filepath{arm-none-eabi-ld} links the object file assigning memory addresses and resolving symbols.
    It reads the file \filepath{babysteps.o} and then the flag \code{-o} indicates the output path \filepath{babysteps.elf}.
    The flag \code{-g} is just a compatibility flag; it is ignored.
\end{itemize}

Now, decomposing the assembly source code, I would describe it as follows:
\begin{itemize}
    \item \code{.global \_start} declares the symbol \code{\_start} as global.
    \item \code{\_start:} indicates that the symbol \code{\_start} starts in that position.
    \item \code{top:} indicates that the symbol \code{top} starts in that position.
    \item \code{eor r1, r1} indicates an XOR operation. The evaluation of r1 \(\oplus\) r1 is assigned to r1.
    \item \code{b top} indicates a jump to the \code{top:} symbol.
\end{itemize}

I would summarize the assembly as the following ``equivalent'' \code{C} code that is more human-readable:

\begin{codebox}[c]{babysteps.c}
int start(){
    int r1;
    while(1){
        r1 = r1 ^ r1;
    }
}
\end{codebox}

It contains an endless loop with an assignment of an XOR operation.
