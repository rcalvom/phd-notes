\begin{codebox}[asm]{babysteps.s}
.global _start

_start:
top:
    eor r1, r1
    b top
\end{codebox}

To build this, I ran the commands recommended in the readings:

\TermHost{ricardo}
\TermPath{homework1}
\TermTitle{Terminal}
\begin{terminal}
\cmd{arm-none-eabi-as -g babysteps.s -o babysteps.o}
\cmd{arm-none-eabi-ld -g babysteps.o -o babysteps.elf}
\end{terminal}

After investigating this myself, I was able to understand what those commands do:

\begin{itemize}
    \item The first command \filepath{arm-none-eabi-as} builds an object file for the ARM architecture.
    It reads the file \filepath{babysteps.s} and then the flag \code{-o} indicates the output path \filepath{babysteps.o}.
    \item The second command \filepath{arm-none-eabi-ld} links the object file assigning memory addresses and resolving symbols.
    It reads the file \filepath{babysteps.o} and then the flag \code{-o} indicates the output path \filepath{babysteps.elf}.
    The flag \code{-g} is just a flag for debugging tools.
\end{itemize}

Now, decomposing the assembly source code, I would describe it as follows:
\begin{itemize}
    \item \code{.global \_start} declares the symbol \code{\_start} as global.
    \item \code{\_start:} indicates that the symbol \code{\_start} starts in that position.
    \item \code{top:} indicates that the symbol \code{top} starts in that position.
    \item \code{eor r1, r1} indicates an XOR operation. The evaluation of r1 \(\oplus\) r1 is assigned to r1.
    \item \code{b top} indicates a jump to the \code{top:} symbol.
\end{itemize}

I would summarize the assembly as the following ``equivalent'' \code{C} code that is more human-readable:

\begin{codebox}[c]{babysteps.c}
int start(){
    int r1;
    while(1){
        r1 = r1 ^ r1;
    }
}
\end{codebox}

It contains an endless loop with an assignment of an XOR operation.

Summarizing the information there:

\begin{itemize}
    \item \textbf{Magic:} Traditional file magic number. The bytes \texttt{7f 45 4c 46} correspond to the ELF magic number.
    \item \textbf{Class:} 32-bit ELF format.
    \item \textbf{Data:} Little-endian representation.
    \item \textbf{Version:} ELF format version.
    \item \textbf{OS/ABI:} Operating system and ABI for which the file was generated.
    \item \textbf{ABI Version:} Version of the specified ABI.
    \item \textbf{Type:} ELF file type. \texttt{EXEC} means that it is an executable file.
    \item \textbf{Machine:} Target processor architecture.
    \item \textbf{Version:} ELF object file version.
    \item \textbf{Entry point address:} Address where program execution begins.
    \item \textbf{Start of program headers:} Offset from the beginning of the file to the program header table.
    \item \textbf{Start of section headers:} Offset from the beginning of the file to the section header table.
    \item \textbf{Flags:} Architecture-specific flags.
    \item \textbf{Size of this header:} Size of the ELF header.
    \item \textbf{Size of program headers:} Size of each entry in the program header table.
    \item \textbf{Number of program headers:} Number of entries in the program header table.
    \item \textbf{Size of section headers:} Size of each entry in the section header table.
    \item \textbf{Number of section headers:} Number of entries in the section header table.
    \item \textbf{Section header string table index:} Specifies which section header contains the string table used to store section names.
\end{itemize}

For this, I modified the file as follows:

\begin{codebox}[asm]{babysteps_serial.s}
.equ UART1_UTXD, 0x02020040

.global _start

_start:
    ldr r0, =message
    ldr r1, =UART1_UTXD

print_character:
    ldrb r2, [r0], #1
    cmp r2, #0
    beq .
    str r2, [r1]
    b print_character

message:
    .asciz "Hello from serial0!\r\n"
\end{codebox}

More details about this:

\begin{itemize}
    \item \code{.equ UART1\_UTXD, 0x02020040} defines the address of the UART1 transmit register, which QEMU connects to the \code{serial0} output.
    \item \code{.global \_start} makes the entry symbol globally visible.
    \item The first two \code{ldr} instructions store the address of the message in \code{r0} and the address of the UART transmit register in \code{r1}.
    \item \code{ldrb r2, [r0], \#1} reads one byte of the message into \code{r2} and increments \code{r0} to point to the next character.
    \item \code{cmp r2, \#0} and \code{beq .} detect the null byte at the end of the string and stay at the current instruction forever.
    \item \code{str r2, [r1]} writes the character to the UART transmit register, and \code{b print\_character} repeats the process for the next character.
    \item \code{.asciz} stores the message with a null byte at the end; \code{\textbackslash r\textbackslash n} are a carriage return and a new line.
\end{itemize}

\section{Modifying our basic code}

Now, let's create the memory checker described in the reading.

I crafted the following file.

\begin{codebox}[asm]{memory_check.s}
.global _start

_start:
    ldr r0, =memory_start
    ldr r1, =memory_end

check_memory:
    ldr r2, [r0], #4
    cmp r2, #0
    bne explode
    cmp r0, r1
    bne check_memory

all_zero:
    b .

explode:
    b .

.data
.align 2
memory_start:
    .word 0
    .word 0
    @ .word 1  @ Uncomment this line to test the nonzero path.
    .word 0
    .word 0
memory_end:
\end{codebox}

Let's go through each point:

\begin{enumerate}
    \item \code{.global \_start} makes the entry symbol globally visible.
    \item The addresses of \code{memory\_start} and \code{memory\_end} define the range that the program checks.
    \item The registers \code{r0} and \code{r1} store the current address and the end address, respectively.
    \item \code{ldr r2, [r0], \#4} reads one 32-bit word into \code{r2} and advances the current address by four bytes.
    \item \code{cmp r2, \#0} and \code{bne explode} transfer execution to \code{explode} when the value is not zero.
    \item \code{cmp r0, r1} and \code{bne check\_memory} repeat the loop until the program reaches the end of the selected memory range.
    \item The \code{all\_zero} and \code{explode} labels use \code{b .} to identify the result and remain at the current instruction forever.
    \item \code{.data} places the test values in the data section, while \code{.align 2} aligns them to a four-byte boundary.
    \item The commented \code{.word 1} line lets me switch between the two cases by commenting or uncommenting it before rebuilding the program.
\end{enumerate}
